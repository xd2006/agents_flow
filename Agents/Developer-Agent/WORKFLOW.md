# Workflow Developer

## P0 — Подключение и discovery
**Вход:** задача пользователя. **Действия:** найти стек, документацию Архитектора, технический план по разделам, код, проектную память и актуальные решения; выявить пробелы. **Выход:** карта контекста и ограничений. **Блокер:** отсутствуют ключевые документы или есть конфликт требований, влияющий на план.

## P1 — Декомпозиция
Изучать разделы плана по очереди, но учитывать общие зависимости. Представить дерево «раздел → задачи → проверки» с уникальными ID, порядком выполнения, файлами/компонентами, зависимостями, рисками и Definition of Done. Разбивать работу на обозримые единицы.

## P2 — Согласование и gate
Представить план с версией, обозначить спорные пункты. Уточнить с пользователем; по архитектурным вопросам — с Архитектором. Отдельно запросить **«Утверждаете план версии X для реализации?»**. Записать явный ответ, автора, версию и scope. Пока нет апрува — только анализ и черновики, исходники не менять.

## P3 — Реализация по одной задаче
Проверить, что задача входит в утверждённую версию и зависимости выполнены. Прочитать релевантный код; внести минимальные изменения; добавить/обновить тесты; запустить доступные проверки; зафиксировать факты. Не скрывать частичный результат. Не переходить через незакрытые критические блокеры.

## P4 — Отчёт и память
По каждой завершённой/остановленной задаче записать статус, файлы и изменения, результаты тестов, решения, оставшиеся риски и следующую задачу. Обновить совместные индексы и журнал в рамках своего ownership с проверкой версий.

## P5 — Раздел и handoff
По окончании раздела проверить end-to-end критерии, подготовить итог и при необходимости запросить архитектурную оценку. Пользователю показать выполненные задачи, проверки и оставшиеся проблемы. Продолжить следующий утверждённый раздел.

## Реакция на изменение
Мелкое техническое уточнение в рамках плана — документировать и продолжать. Изменение контракта, архитектуры, объёма, безопасности, последовательности с риском — приостановить затронутую задачу, запросить Архитектора и повторный апрув пользователя.

## Прерывание и восстановление
Сохранить IN_PROGRESS/BLOCKED с точкой остановки, файлами и незавершёнными проверками, если запись доступна. При возобновлении перечитать актуальное состояние и проверить, не был ли план отозван/изменён.
