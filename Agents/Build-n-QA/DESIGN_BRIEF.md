# Финальный дизайн-бриф Build-n-QA

## Миссия
Автоматизировать цикл подготовки изолированной Unity Android-сборки, извлечения GDD-тестов, визуального QA в установленном Android-эмуляторе, передачи дефектов Developer и проверки исправлений до 100% PASS обязательных тестов.

## Подтверждённые пользователем решения (`CONFIRMED DECISION`)
1. Движок Unity; целевая платформа Android; выход только Development/Debug APK для тестирования.
2. Среда исполнения — **другая агентная среда**, конкретный runtime не назван.
3. Основной Unity-проект нельзя изменять силами Build-n-QA. Временная полная копия разрешена для интеграции ассетов и настройки сборки.
4. Ассеты предоставляют другие AI-агенты.
5. Тесты получает от GDD-агента или выводит из доступного GDD в зависимости от доступности данных.
6. QA — автономное управление установленным эмулятором: касания, свайпы, чтение экрана, сравнение поведения с ожиданиями.
7. Build-n-QA ищет **уже установленный** эмулятор, не устанавливает новый самостоятельно.
8. Developer и GDD-агент существуют в другой агентной системе; Developer вызывается напрямую через subagent/orchestration.
9. Баги — структурированные Markdown-отчёты + прямая передача Developer.
10. После исправлений Developer производится новое QA; условие успешного завершения — все обязательные кейсы `PASS`.
11. **Нет согласований между фазами**. Вопрос к пользователю допустим только при блокирующем отсутствии информации, доступа, инструмента или полномочия.

## Ответственность
Build-n-QA: preflight → staging → сборка APK → тест-план → UI-автоматизация → отчёт → разработчик → retest.  
Developer: изменение исходников и исправление дефектов.  
GDD-агент: канонические требования и разрешение противоречий GDD.  
Ассет-агенты: исходные ассеты и метаданные версий.

## Основная последовательность
`DISCOVER → STAGE/BUILD → GET_CASES → TEST → [REPORT/HANDOFF → DEVELOPER_FIX → NEW_BUILD → RETEST]* → DONE`

Переходы автоматические. Если билд сломан, допустим ранний handoff с ошибками сборки. При `BLOCKED` запросить только действительно отсутствующие данные; частичный результат не считать успехом.

## Граница «проект нельзя изменять»
**Инвариант:** оригинальная папка Unity доступна Build-n-QA только на чтение. Любые интеграции ассетов, изменения `ProjectSettings`, временные Editor-build-скрипты и сборка исполняются внутри отдельной рабочей копии. Logs, APK и память располагаются **вне оригинального дерева Unity-проекта**. Developer сам отвечает за изменения канонических исходников в своём контуре.

## Память и результаты
Для конфликта между стандартной моделью `Agent_Memory` внутри проекта и запретом изменять оригинал выбран портируемый default: `workspace_root/Agent_Memory` (вне исходного проекта) + `workspace_root/QA_Artifacts`. Это технический default, не новое требование пользователя; пути могут быть переопределены при сохранении запрета записи в source.

## Риски и зависимости для запуска (`OPEN QUESTION` / runtime blocker)
- Не указан конкретный оркестратор и API вызова subagent; нужны реальные подключения к GDD-агенту и Developer.
- Не указаны фактические локальные пути, установленная Unity/Android Build Support/SDK/ADB/лицензия, эмулятор, версия проекта, точка входа сборки.
- Не указан конкретный API ассет-агентов и схема поставки; по умолчанию использовать manifest + checksum.
- Не подтверждено наличие у выбранной агентной среды **визуального восприятия скриншотов и управления Android-эмулятором**. Без них «автономное визуальное QA» технически невозможно.

Эти неизвестные **не блокируют создание спецификации**. Они блокируют только её реальное исполнение. Адаптеры запрещено объявлять работающими до фактического capability test.

## Условия успеха
- Debug APK создан и идентифицирован хешем; оригинальный проект не изменён действием Build-n-QA.
- Набор обязательных тестов привязан к конкретной версии GDD/билда.
- 100% обязательных тестов реально выполнены и имеют `PASS` с проверяемым evidence.
- Нет неразрешённых дефектов, нарушающих эти кейсы. Результаты документированы и переданы соответствующим агентам.
- При невыполнимости указано `BLOCKED`/`FAILED`, а не ложный `DONE`.
