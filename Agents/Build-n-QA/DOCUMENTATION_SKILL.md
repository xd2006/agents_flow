# DOCUMENTATION_SKILL

**Trigger:** на завершении задачи, при `BLOCKED/FAILED/STALLED`, а также на checkpoint после крупных фаз и перед передачей Developer, если это необходимо для восстановления.

**Цель:** воспроизводимый след действий без ложных утверждений о файловых записях.

1. Сохранить `task-report.md` по `templates/TASK_REPORT.md` во внешнем workspace (`QA_Artifacts/Build-n-QA/<task_id>/<run_id>/`).
2. Обязательно указать `task_id`, `run_id`, фактический timestamp/timezone **если доступен**, agent, статус, цель, входы, исходную/GDD/asset ревизии, шаги, build hash, реальные tool results, результаты тестов, решения, блокеры, следующие действия.
3. Перечислить только действительно созданные/изменённые файлы и их ссылки/хеши.
4. Заполнить `Agent_Memory/Build-n-QA/WORK_LOG.md`; обновить task checkpoint и затронутые shared indexes по `MEMORY_RULES.md`.
5. Удалять/редактировать документы только по правам workspace; сохранять историю багов и версий, не перетирать чужие данные.
6. Прочитать назад записанный файл или проверить подтверждение runtime. Если подтверждения нет, писать «не удалось сохранить», не «сохранено».

**Output:** `task-report.md`, запись work log, соответствующие изменения индексов. При отказе записи сообщить невозможность персистентности.
