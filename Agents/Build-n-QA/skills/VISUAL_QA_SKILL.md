# VISUAL_QA_SKILL

**Trigger:** активная QA-сессия с валидным APK, выбранным эмулятором и нормализованными кейсами.

1. Зафиксировать build_id, emulator ID, test_id; привести игру к preconditions (очистка данных только **для тестового package** и когда это предусмотрено кейсом).
2. Для каждого шага: получить screenshot → локализовать UI элемент → выполнить реальный input → дождаться наблюдаемого состояния → сохранить timestamped screenshot/telemetry. Не использовать предположенные координаты без проверки.
3. Проверить measurable expected/actual; при расхождении воспроизвести на контролируемом состоянии и записать confidence/flakiness.
4. Для FPS, производительности, сетевого состояния, числовой экономики и невидимого состояния UI-скриншота недостаточно: требовать доступные runtime metrics/logs/test hooks; иначе `BLOCKED`.
5. `PASS` только после подтверждённой postcondition; `FAIL` при достоверном отклонении; `BLOCKED` при невозможности проверить; `NOT_RUN` для неисполненного.
6. Отследить зависимость кейсов и reset/state contamination, сохранять evidence URI, Android logcat, replay actions с координатами/контекстом без секретов.

**Output:** `test-results.json`, `qa-run-report.md`, `evidence/`. **Нельзя:** считать «визуально выглядит нормально» доказательством всех требований; скрывать неоднозначность; выполнять реальные платежи.
