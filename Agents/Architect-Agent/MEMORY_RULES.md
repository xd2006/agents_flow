# MEMORY_RULES: Архитектор

## Структура папок
```
<project>/
  docs_setup/                 # стек проекта (читает Архитектор)
  agents/                     # описания агентов (читает Архитектор)
  Agent_Memory/
    _Shared/
      PROJECT_STATE.md
      DECISIONS.md
      CONFLICTS.md
      TASK_BOARD.md
      ARTIFACT_INDEX.md
    _Mailbox/
      Architect/              # входящие для Архитектора (вопросы Разработчика, ответы агентов)
      Developer/              # входящие для Разработчика (ответы Архитектора, уведомления о правках)
      Producer/
      Artist/
      SoundDesigner/
    Architect/
      MEMORY.md
      WORK_LOG.md
      DECISION_LOG.md
      OPEN_QUESTIONS.md
      tasks/
```

## Владение
- Архитектор владеет: `Architect/`, ARCHITECTURE.md, DEV_INSTRUCTIONS.md, ENVIRONMENT.md, ARTIFACT_INDEX.md (только свои строки), TASK_BOARD.md (этапы), DECISIONS.md (архитектурные решения).
- Разработчик владеет: статусами своих задач в TASK_BOARD.md и своими отчётами в `_Mailbox/Architect/`.
- Продюсер, Художник, Саунд-дизайнер владеют своими реестрами и своими папками в `_Mailbox/`.

## Правила чтения
1. Перед работой читай PROJECT_STATE.md, DECISIONS.md, CONFLICTS.md, TASK_BOARD.md, ARTIFACT_INDEX.md и `_Mailbox/Architect/` (только со статусом OPEN).
2. Не читай всё подряд: переходи по ссылкам из ARTIFACT_INDEX.md.

## Правила записи
1. Пиши в конце задачи, а не непрерывно. Исключение: статус BLOCKED или IN_PROGRESS при прерывании.
2. Перед записью в общий файл перечитай его. Если версия изменилась, не перезаписывай: запиши конфликт в CONFLICTS.md и сообщи пользователю.
3. Записывай только свои строки в чужие файлы, если это явно разрешено владением.
4. CONFIRMED-решения не меняй без пользователя.
5. Не утверждай, что файл записан, без подтверждения записи.

## Почтовый ящик (mailbox)
Файл: `_Mailbox/<Agent>/<YYYY-MM-DD>_<id>_<тема>.md`
Поля заголовка: id, от, кому, статус (OPEN | ANSWERED | CLOSED), приоритет (BLOCKING | NORMAL), ссылка на связанную задачу.
Правила:
- Ответ пишется отдельным файлом в ящик отправителя, исходный файл не удаляется.
- Закрывает запрос тот, кто его создал: переводит статус в CLOSED.
- Вопрос Разработчика со статусом BLOCKING Архитектор обрабатывает в первую очередь.

## Конфликты
Любое противоречие между источниками, агентами или решениями записывается в CONFLICTS.md с указанием источников, статуса и владельца решения.

## Запреты
- Не сохраняй секреты, ключи, пароли и токены в Agent_Memory и в репозитории.
- Не выдумывай содержимое файлов, которые не читал.
