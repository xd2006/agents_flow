# OUTPUT_CONTRACT: Архитектор

## Обязательные выходы
| Файл | Расположение | Назначение |
|---|---|---|
| ARCHITECTURE.md | `<project>/docs/` (уточняется при запуске) | Архитектура проекта |
| ENVIRONMENT.md | `<project>/docs/` | Среда разработки и команды установки |
| DEV_INSTRUCTIONS.md | `<project>/docs/` | Инструкция для Разработчика |
| Структура репозитория | корень репозитория | Папки, .gitignore, шаблоны |
| Отчёт о проверке этапа | `Agent_Memory/Architect/tasks/` | Результат PASS, FAIL или PARTIAL |

Если путь `<project>/docs/` не согласован с docs_setup, сначала фиксируется решение (DEC) о месте документации.

## ARCHITECTURE.md: обязательные разделы
1. Обзор и цели.
2. Стек и версии (со ссылкой на docs_setup).
3. Модули и их ответственность.
4. Потоки данных и состояния.
5. Интеграция ассетов (правила, реестр).
6. Интеграция звуков (правила, реестр).
7. Структура репозитория.
8. Нефункциональные требования (производительность, платформы).
9. Открытые вопросы и решения.

## ENVIRONMENT.md: обязательные разделы
1. Требования к машине.
2. Список инструментов с версиями.
3. Пошаговая установка, пригодная для повтора.
4. Команды проверки (сборка пустого проекта).
5. Известные ограничения.

## DEV_INSTRUCTIONS.md: обязательные разделы
1. Порядок этапов и зависимостей.
2. Для каждого этапа: цель, задачи, входы, выход, критерии готовности, способ проверки, точка проверки (да или нет).
3. Правила работы с Архитектором: как задавать вопросы, как сообщать о правках кода.
4. Правила коммитов и веток (если согласованы пользователем).

## Формат отчёта о проверке этапа
```
# Stage Review: <этап>
- Статус: PASS | FAIL | PARTIAL
- Дата: <если доступна>
- Критерии: <список с PASS/FAIL/NOT RUN>
- Замечания: <список>
- Решение о переходе: <кто принимает>
- Следующие шаги: <владелец и срок, если известен>
```

## Качество
- Документы на русском, термины в оригинале.
- Нет утверждений без источника.
- Каждый пункт инструкции проверяем.
- Все открытые вопросы имеют владельца.
