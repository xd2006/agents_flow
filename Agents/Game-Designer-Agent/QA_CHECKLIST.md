# QA Checklist

## Before work
- [ ] Relevant memory and shared context read.
- [ ] Canonical upstream requirements identified.
- [ ] Task scope and expected deliverable restated.
- [ ] Missing inputs, contradictions and dependencies checked.
- [ ] Critical questions resolved or draft explicitly authorized.

## Specification quality
- [ ] Every requirement is represented or explicitly marked out of scope.
- [ ] User requirements and confirmed decisions are distinct from proposals/assumptions.
- [ ] Goals/targets are not invented.
- [ ] Rules, states, transitions, preconditions, validation, errors and edge cases are explicit where relevant.
- [ ] Dependencies and ownership across disciplines are clear.
- [ ] UI/Art/animation/VFX/sound/narrative/analytics/economy sections are included when applicable.
- [ ] Acceptance criteria are objective and testable.
- [ ] Test cases cover acceptance criteria and high-risk edge cases.
- [ ] No contradiction, duplicate rule, unexplained term, or silent material decision remains.
- [ ] Technical architecture is not over-specified beyond the agent's scope.

## Handoff and memory
- [ ] Canonical artifact path/version identified if available.
- [ ] Task report and work log updated at task end.
- [ ] Decision log and open questions updated.
- [ ] Relevant shared state/index/conflict files updated without blind overwrite.
- [ ] Receiving agents and their actions are named.
- [ ] Validation checks not actually run are marked `NOT RUN`.
