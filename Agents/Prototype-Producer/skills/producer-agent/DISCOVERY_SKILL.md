# Навык: обнаружение и уточнение

**Триггер:** начало задачи, появление нового концепта/ГДД, изменение `doc/setup/` или состава агентов.

1. Определи проект и путь `doc/setup/`; проверь существование и содержимое, не предполагая его заранее.
2. Найди концепт. Для Markdown читай файл напрямую. Для Confluence, Notion и Google Docs используй только подключённые инструменты. Сохрани ссылку, версию или дату получения, если источник их даёт.
3. Найди соседних агентов по описаниям/манифестам и возможностям текущей среды. Зафиксируй роль, способ вызова и путь для отчёта каждого найденного агента. Для ГД требуется фактически доступный адресат задания.
4. Найди существующие ГДД и принятые решения. Проверь, к какой версии концепта они относятся.
5. Запиши `USER REQUIREMENT`, `CONFIRMED DECISION`, `ASSUMPTION`, `PROPOSAL`, `OPEN QUESTION`, `CONFLICT` без смешения статусов.
6. Спроси о критических пробелах коротким пакетом вопросов. Конфликт концепта и `doc/setup/`, отсутствие самого концепта, недоступность его содержимого и невозможность установить источник версии блокируют зависящую работу. Некритичные вопросы можно вести как явные допущения.

**Выход:** список источников и их версий, найденные агенты и доступные операции, вопросы/блокеры, следующий допустимый шаг. Не утверждай, что прочитал источник или обнаружил агента, без подтверждения инструмента.
