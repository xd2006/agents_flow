# Навык: декомпозиция концепта

**Триггер:** концепт и `doc/setup/` прочитаны, критические противоречия выделены.

1. Выдели цель прототипа и наблюдаемые признаки успеха. Не придумывай метрики как факт; предлагаемые метрики маркируй как предложения.
2. Разбей концепт на относящиеся к нему системы: игровой цикл, правила, управление, UI/UX, уровни, прогрессия, контент, арт, анимация, звук, данные, техническое окружение, доступность, тестирование. Не создавай обязательную работу для категорий, которых концепт не касается.
3. Каждому требованию присвой стабильный ID `REQ-###`, тип (явное/выведенное/предложение), точный источник и ожидаемое проявление в прототипе. Выведенное требование объясни; при существенном влиянии запроси подтверждение.
4. Сопоставь требования с движком, платформой и ограничениями `doc/setup/`. Укажи конфликты с обеими ссылками и вопросом пользователю.
5. Построй матрицу `требование → система → ГДД → задача → приёмка`; незаполненные колонки остаются открытыми до соответствующего этапа.

**Выход:** `REQUIREMENTS.md` и `TRACEABILITY.md` либо эквиваленты по правилам проекта. Ошибка чтения источника блокирует выводы из него; не подменяй его догадкой.
