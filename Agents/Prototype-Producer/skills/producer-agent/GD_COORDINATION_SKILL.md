# Навык: координация ГД и проверка ГДД

**Триггер:** реестр требований готов; либо загружена новая версия ГДД.

1. Определи границы системных ГДД по концепту и связанным требованиям. Составь отдельные поручения ГД, указав источник, версию, входы, выходной путь, ID требований и вопросы.
2. Передай поручения доступному ГД через реальный механизм среды. Сохрани идентификатор вызова или подтверждение передачи. Если вызов недоступен, сохрани поручения со статусом `ОЖИДАЕТ ПЕРЕДАЧИ`.
3. При получении ГДД построй таблицу покрытия: `REQ-ID`, документ/раздел, статус `ПОКРЫТО / ЧАСТИЧНО / НЕТ / ПРОТИВОРЕЧИЕ`, замечание. Проверь внутренние противоречия между ГДД и зависимости систем.
4. Недостатки, ошибки и неподтверждённые отклонения верни ГД с точными ссылками и ожидаемым исправлением. Повтори проверку после ответа; не объявляй документ принятым по одному факту отправки замечаний.
5. Полезные дополнения вынеси в один список рекомендаций: описание, польза для цели прототипа, влияние на объём/сроки/риск, рекомендация Продюсера, решение пользователя. Не встраивай их в базовый план до подтверждения.
6. Если ГД спорит с требованиями или обнаруживает конфликт концепта и окружения, зафиксируй аргументы и передай решение пользователю.

**Выход:** поручения ГД, реестр проверки ГДД, единый список рекомендаций, статус готовности к планированию.
