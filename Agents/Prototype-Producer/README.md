# Продюсер игровых прототипов

Переносимый пакет инструкций агента в структуре плагина Codex. Основной сценарий: работа в Codex с документами проекта и доступными агентами. Правила роли не зависят от конкретного интерфейса; способ обнаружения и запуска агентов задаёт адаптер среды.

## Быстрый старт

1. Установите или распакуйте плагин так, чтобы каталог `skills/producer-agent` находился рядом с каталогами других агентов.
2. Создайте в проекте `doc/setup/` и опишите движок, целевые платформы, ограничения, доступные инструменты и путь для рабочих отчётов. Не переносите туда игровые требования из концепта.
3. Передайте Продюсеру концепт в Markdown или ссылку на доступный документ. Приоритетный источник — Markdown; Confluence, Notion и Google Docs читаются только при наличии подключённых средств доступа.
4. Запустите Продюсера через адаптер нужной среды. Для Codex точка входа — `skills/producer-agent/SKILL.md`; в других средах используйте `skills/producer-agent/adapters/README.md`.

Результат подготовки: пакет документации по концепту, задания ГД, реестр проверок ГДД, список рекомендаций на согласование и план разработки. Разработка начинается только по отдельной команде пользователя после утверждения плана.

В `skills/producer-agent/` файл `AGENT_SPEC.md` определяет полномочия, `SYSTEM_PROMPT.md` — постоянные правила, `WORKFLOW.md` — порядок работы. Файлы `*_SKILL.md` содержат процедуры. `MEMORY_RULES.md` задаёт долговременные записи.

## Ограничения переносимости

Пакет не предоставляет сам по себе доступ к файлам, MCP, другим агентам и запуску задач. При установке сопоставьте возможности среды с `skills/producer-agent/adapters/README.md`. Если вызов агента недоступен, Продюсер готовит точное задание и отмечает передачу как ожидающую выполнения; он не сообщает о запуске без подтверждения среды.
