# Рабочий процесс

## 1. Discovery

Вход: запрос пользователя и доступные проектные материалы.

1. Прочитать DISCOVERY_SKILL.
2. Найти инструкции проекта, концепт-документ и существующий артстайл-гайд.
3. Определить формат и папку результата по иерархии проектных правил.
4. Составить перечень требований и референсов с их источниками.

Выход: понятен целевой путь и набор допустимых входов, либо сформулирован блокирующий вопрос.

## 2. Проверка полноты

1. Сопоставить требования с категориями гайда.
2. Проверить, есть ли в концепт-доке изображения-референсы.
3. Если изображений нет либо их недостаточно для заявленных ориентиров, запросить у пользователя конкретные недостающие материалы.
4. Не переходить к сохранению референсов до получения разрешённых файлов или явного указания пользователя продолжать без них.

## 3. Подготовка гайда

1. Сформировать текст по OUTPUT_CONTRACT.
2. Отделить подтверждённые требования от PROPOSAL и ASSUMPTION.
3. Добавить ссылки на локальные референсы только после их успешного размещения.
4. Проверить, что все существенные элементы объяснены текстом.

## 4. Размещение артефактов

1. Следовать проектному соглашению об именах и папках.
2. При отсутствии отдельного соглашения использовать папку references рядом с согласованным файлом гайда.
3. Давать файлам стабильные описательные имена и не перезаписывать существующие файлы без проверки.
4. Убедиться, что относительные ссылки работают из расположения гайда.

## 5. QA и отчёт

1. Пройти QA_CHECKLIST.
2. Обновить документацию и журнал решений, если они разрешены.
3. Сообщить статус DONE, PARTIAL или BLOCKED, канонический путь, референсы и дальнейшее действие.

## Recovery

При конфликте между входами не выбирай сторону молча: укажи конфликт и запроси решение. При ошибке доступа сохрани только подтверждённый прогресс и сообщи точную причину. При прерывании зафиксируй IN_PROGRESS, если доступна память.
