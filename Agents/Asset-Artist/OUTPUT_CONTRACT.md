# OUTPUT_CONTRACT — Asset Artist

Если Format_Specs задают другую структуру, нейминг или форматы, приоритет у Format_Specs. Ниже описаны дефолты на этот случай.

## 1. Структура `Assets/`

```text
Assets/
  ASSET_MANIFEST.md        # канонический реестр ассетов
  <category>/              # ui, icons, tiles, characters, backgrounds, vfx, ... (категории из Format_Specs, иначе эти)
    <versioned files>
  export/                  # PROPOSAL: копии последних APPROVED-версий под стабильными именами для интеграции
  _src/                    # исходники: .svg, canvas-скрипты, многослойные рабочие файлы
  _style_tests/ST-###/     # style test: ассеты, мокап, STYLE_TEST.md
  _prompts/                # пакеты промптов для внешней генерации (T3)
  _incoming/<asset_id>/    # результаты внешней генерации на проверку
```

## 2. Нейминг
Шаблон:

`<category>_<name>[_<state>][_<variant>]_v<NNN>[@<N>x].<ext>`

- Только латиница в нижнем регистре, snake_case, без пробелов.
- Версия трёхзначная. Плотность указывается суффиксом, если плотностей несколько.
- Пример: `ui_btn_play_pressed_v002@2x.png`.
- В `export/` версия не пишется: `ui_btn_play_pressed@2x.png`.

## 3. Версии
- Существующая версия никогда не перезаписывается. Правка означает новую версию.
- Каноническая версия — та, у которой в манифесте статус `APPROVED`. Если её нет, каноническая последняя `READY_FOR_REVIEW`.
- Старые версии остаются на месте со статусом `SUPERSEDED`.
- `export/` производна от манифеста и пересобирается из `APPROVED`. Перезапись внутри `export/` разрешена.

## 4. Манифест
Шаблон: `templates/ASSET_MANIFEST.md`. Одна строка на ассет: состояние × версия. Плотности перечисляются в той же строке.

| Поле | Содержание |
|---|---|
| `asset_id` | `AS-####`, стабилен между версиями |
| `file` | путь |
| `category`, `state` | категория и состояние |
| `size_px` | базовый размер; `densities` |
| `format`, `alpha` | формат и наличие прозрачности |
| `method` | `T1` / `T2:<tool>` / `T3` |
| `source` | путь в `_src/` или файл промпта, параметры генерации (seed и прочее, если есть) |
| `inputs` | версии входов (ID из `INPUT_REGISTRY.md`) |
| `status` | см. раздел 5 |
| `qa` | `PASS` / `FAIL` / `NOT_VERIFIED`, раздельно для тех. и визуальной части |
| `notes` | допущения, ссылки на REQ/DEC/фидбек |

## 5. Статусы ассета
- `PLANNED`: в плане.
- `BLOCKED`: заблокирован, обязательна ссылка на REQ или конфликт.
- `IN_PROGRESS`: в работе.
- `AWAITING_EXTERNAL`: ждёт внешней генерации (T3).
- `READY_FOR_REVIEW`: готов к ревью.
- `CHANGES_REQUESTED`: пользователь запросил правки.
- `APPROVED`: утверждён, ставит только пользователь.
- `FAILED_QA`: не прошёл QA после итераций.
- `NEEDS_REVIEW`: изменился вход после выдачи.
- `SUPERSEDED`: заменён новой версией.

## 6. Итоговое сообщение пользователю
Коротко, на языке пользователя:
1. **Статус задачи:** `DONE` / `PARTIAL` / `BLOCKED` / `FAILED`.
2. **Готово:** ассеты с путями. Если их много, сводка и ссылка на манифест.
3. **Нужно от пользователя:** утвердить style test, ответить на визуальные вопросы, запустить внешнюю генерацию.
4. **Заблокировано:** что и почему, ID запросов и их адресаты.
5. **Допущения**, которые стоит проверить.
6. **Что не проверено**, например визуальный QA без просмотра изображений.

## 7. Definition of Done

**Ассет:**
- файл существует по пути из манифеста;
- соответствует Format_Specs;
- технический QA `PASS`;
- визуальный QA `PASS` или явно `NOT_VERIFIED` с запросом на проверку человеком;
- строка в манифесте заполнена полностью;
- допущения помечены;
- исходник или параметры генерации сохранены;
- статус `READY_FOR_REVIEW` или выше.

**Задача:**
- каждый ассет из объёма задачи находится в `READY_FOR_REVIEW` / `APPROVED` либо в `BLOCKED` / `AWAITING_EXTERNAL` / `FAILED_QA` с объяснением и ссылкой;
- отчёт задачи записан;
- обновлены `ARTIFACT_INDEX.md`, `TASK_BOARD.md`, `INPUT_REGISTRY.md`;
- итоговое сообщение дано.

## 8. Частичный и заблокированный результат
- `PARTIAL`: часть ассетов готова, остальные заблокированы или ждут. В отчёте указан список по статусам.
- `BLOCKED`: ничего не произведено из-за `BLOCKER-ALL`. В отчёте указаны запросы и что нужно для старта.
- `FAILED`: технический сбой без обхода. В отчёте указаны описание, попытки и предложения.
