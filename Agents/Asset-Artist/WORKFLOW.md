# WORKFLOW — Asset Artist

Агент работает по вызову (A-05). Каждый запуск проходит фазы по порядку. Если фаза не может завершиться, задача закрывается со статусом `BLOCKED` или `PARTIAL`, и следующий запуск продолжает с сохранённого состояния.

## Фаза 0. Preflight
- **Вход:** получена задача от пользователя или из `TASK_BOARD.md`.
- **Действия:**
  1. Прочитай память по `MEMORY_RULES.md`, раздел 3. Если файлов памяти нет, создай их по разделу 2.
  2. Проверь свои незакрытые задачи (`IN_PROGRESS`, `BLOCKED`) и запросы `REQ-AA-*` со статусом `ANSWERED`.
  3. Определи доступные возможности (`skills/ASSET_PRODUCTION_SKILL.md`, раздел 1).
- **Выход:** известны контекст, возможности и незакрытые хвосты.

## Фаза 1. Discovery
- **Вход:** фаза 0 пройдена.
- **Действия:** выполни `DISCOVERY_SKILL.md` и `skills/INPUT_INTAKE_SKILL.md`: прочитай все четыре входа, сверь их с `INPUT_REGISTRY.md`, найди пробелы, противоречия и изменения.
- **Выход:** есть Asset Brief задачи, у каждого пробела есть класс блокировки.
- **Если входы изменились** после выдачи ассетов: пометь затронутые ассеты `NEEDS_REVIEW` и сообщи пользователю.

## Фаза 2. Запросы
- **Вход:** есть пробелы или конфликты.
- **Действия:** оформи запрос по `skills/INPUT_REQUEST_SKILL.md`, один на адресата и связанную группу вопросов; адресат — по разделу 1 навыка. Запиши конфликты в `CONFLICTS.md`.
- **Выход:**
  - `BLOCKER-ALL`: переход к фазе 8 со статусом `BLOCKED`.
  - `BLOCKER`: заблокированные ассеты исключаются из плана.
  - `NON-BLOCKING`: работа идёт с пометкой `ASSUMPTION`.

## Фаза 3. План
- **Действия:** составь список ассетов (ID, состояния, размеры, метод T1/T2/T3, используемые рефы) по `skills/ASSET_PRODUCTION_SKILL.md`, раздел 2. Выведенные позиции, которых явно нет в GDD или задаче, помечай `PROPOSAL`.
- **Выход:** план записан в отчёт задачи, ассеты в манифесте имеют статус `PLANNED` или `BLOCKED`.

## Фаза 4. Style test (гейт)
- **Когда нужен:** если для проекта ещё нет утверждённого style test или задача вводит новую категорию ассетов, стиль которой не проверялся.
- **Действия:** сделай 2–3 показательных ассета и мокап в контексте экрана, а затем запроси утверждение у пользователя (`skills/ASSET_PRODUCTION_SKILL.md`, раздел 3).
- **Выход:**
  - Утверждено: style profile получает статус `CONFIRMED`, переход к фазе 5.
  - Не утверждено: итерация или фаза 8 со статусом `PARTIAL` и ожиданием ревью.
- **Исключение:** плейсхолдеры (greybox) по прямому заказу пользователя проходят без style test.

## Фаза 5. Производство
- **Действия:** создавай ассеты выбранными методами, постобрабатывай, сохраняй исходники и параметры генерации. Для T3 готовь пакеты промптов (статус `AWAITING_EXTERNAL`).
- **Выход:** у каждого ассета из плана есть файл-кандидат или обоснованный статус.

## Фаза 6. Проверка
- **Действия:** прогони `skills/ASSET_VALIDATION_SKILL.md` по `QA_CHECKLIST.md`. Найденные ошибки исправляй до 2 итераций, после этого фиксируй как `FAILED_QA`.
- **Выход:** у каждого ассета есть результат QA (`PASS`, `FAIL` или `NOT_VERIFIED` для визуальной части).

## Фаза 7. Выдача
- **Действия:** выложи ассеты по `OUTPUT_CONTRACT.md`, обнови манифест, `ARTIFACT_INDEX.md`, `TASK_BOARD.md` и раздел «Графика» в `PROJECT_STATE.md`. Добавь в `TASK_BOARD.md` handoff-строку для `developer_agent`.
- **Выход:** ассеты получают статус `READY_FOR_REVIEW`. Статус `APPROVED` ставится только после подтверждения пользователя.

## Фаза 8. Закрытие
- **Действия:** запиши отчёт задачи (`DOCUMENTATION_SKILL.md`), решения (`DECISION_LOG_SKILL.md`), обнови `OPEN_QUESTIONS.md`, `MEMORY.md` и `INPUT_REGISTRY.md`. Дай итоговое сообщение по `OUTPUT_CONTRACT.md`, раздел 6.

## Повторный вход

| Событие | С какой фазы |
|---|---|
| Запрос получил ответ (`ANSWERED`) | 1: перечитать изменённые входы, закрыть или продолжить запрос |
| Пользователь утвердил style test | 5 |
| Пользователь запросил правки (`CHANGES_REQUESTED`) | 5: новая версия со ссылкой на фидбек |
| Внешняя генерация положила файлы в `_incoming/` | 6 |
| Изменился вход после выдачи | 1: пометить затронутые ассеты `NEEDS_REVIEW` |
| Прерванная задача (`IN_PROGRESS`) | фаза, записанная в отчёте |
