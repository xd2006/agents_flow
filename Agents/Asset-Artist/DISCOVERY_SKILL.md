# DISCOVERY_SKILL — разведка перед работой

## Назначение
Не начинать производство, пока не понятно, что делать, из чего, по каким правилам и чего не хватает.

## Когда вызывать
В начале каждой задачи и при каждом повторном входе (`WORKFLOW.md`).

## Процедура
1. **Контекст.** Прочитай память по `MEMORY_RULES.md`, раздел 3.
2. **Цель.** Перескажи задачу одной-двумя фразами: какие ассеты, для чего, в каком объёме. Если формулировка допускает разные толкования объёма, это `OPEN QUESTION` к пользователю.
3. **Входы.** Выполни `skills/INPUT_INTAKE_SKILL.md`: прочитай четыре входа, проверь полноту по чек-листам, сверь с `INPUT_REGISTRY.md`.
4. **Неизвестные.** Составь список: чего не хватает, где есть противоречия, какие входы изменились, на какие внешние зависимости ты опираешься (инструменты, чужие задачи).
5. **Классификация.** Присвой каждому пункту класс:
   - `BLOCKER-ALL`: без этого нельзя делать ни один ассет задачи. Примеры: нет стайл-гайда; нет ни GDD, ни списка ассетов.
   - `BLOCKER`: блокирует конкретные ассеты или финальный экспорт. Примеры: неизвестен размер иконок; не описаны состояния кнопки.
   - `NON-BLOCKING`: есть безопасный обратимый дефолт. Пример: не задан padding в атласе, по умолчанию 2 px.
   - `INFO`: полезно, но на результат не влияет.
6. **Дефолты.** Для `NON-BLOCKING` запиши дефолт как `ASSUMPTION`: основание и влияние.
7. **Вопросы.** Всё, что имеет класс `BLOCKER*`, и все существенные `ASSUMPTION` передай в `skills/INPUT_REQUEST_SKILL.md`. Адресата выбирай по `skills/INPUT_REQUEST_SKILL.md`, раздел 1: стайл-гайд, требования к ассетам, рефы и визуальные вопросы → `art_style_guide_agent`; GDD → `game_designer_agent`; движок и требования интеграции → `developer_agent`; утверждение style test и ассетов → пользователь.
8. **Asset Brief.** Запиши в отчёт задачи:
   - цель;
   - объём;
   - версии использованных входов;
   - доступные режимы T1/T2/T3;
   - список пробелов с классами;
   - список допущений;
   - что можно делать сейчас.

## Запреты
- Не начинать генерацию, пока есть открытый `BLOCKER-ALL`. Исключение: плейсхолдеры по прямому заказу пользователя.
- Не превращать догадку в требование. Вывод из рефа без подтверждения остаётся `PROPOSAL`.
- Не задавать вопросы, ответ на которые уже есть во входах или в `CONFIRMED`-решениях.

## Выход
Asset Brief в отчёте задачи, обновлённый `OPEN_QUESTIONS.md`, при необходимости запрос `REQ-AA-####`.
