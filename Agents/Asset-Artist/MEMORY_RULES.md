# MEMORY_RULES — память Asset Artist

## 1. Принцип
Память агента — это файлы. Воспоминания из переписки ею не являются. Никогда не утверждай, что прочитал или записал файл, без подтверждения инструмента.

## 2. Структура

```text
<Game_Project>/
  Agent_Memory/
    _Shared/
      PROJECT_STATE.md      # принятое состояние проекта (агент правит только раздел «Графика»)
      DECISIONS.md          # CONFIRMED-решения, затрагивающие нескольких агентов (только добавление)
      CONFLICTS.md          # нерешённые конфликты между входами/агентами
      TASK_BOARD.md         # задачи: статус, владелец, зависимости
      ARTIFACT_INDEX.md     # ссылки на канонические артефакты
      REQUESTS/             # запросы между агентами
        REQ-AA-####.md
    Asset_Artist/
      MEMORY.md             # устойчивые знания: ссылки на style profile, выбранные методы, особенности инструментов, уроки
      STYLE_PROFILE.md      # операционные параметры стиля, извлечённые из гайда и утверждённые на style test
      INPUT_REGISTRY.md     # версии/хеши входов и по каким версиям сделаны ассеты
      WORK_LOG.md
      DECISION_LOG.md
      OPEN_QUESTIONS.md     # открытые вопросы со ссылками на REQ/CONFLICT
      tasks/
        TASK-AA-####.md
```

**Bootstrap.** Если при первом запуске файлов нет, создай недостающие файлы: с заголовками из `templates/`, где шаблон есть, иначе пустые с заголовком. Существующие файлы не пересоздавай и не очищай.

## 3. Что читать перед работой
Минимальный набор, без чтения всего подряд:
1. `Asset_Artist/MEMORY.md`, `STYLE_PROFILE.md`, `INPUT_REGISTRY.md`, `OPEN_QUESTIONS.md`.
2. Отчёты своих незакрытых задач (`IN_PROGRESS`, `BLOCKED`).
3. `_Shared/PROJECT_STATE.md`, `_Shared/DECISIONS.md`.
4. Свои строки в `_Shared/TASK_BOARD.md`.
5. Свои запросы в `_Shared/REQUESTS/`, особенно со статусом `ANSWERED`.
6. `_Shared/CONFLICTS.md`: записи, касающиеся графики.
7. Только те файлы из `ARTIFACT_INDEX.md`, которые нужны задаче.

## 4. Когда писать
- В конце задачи (`DOCUMENTATION_SKILL.md`). Непрерывно память не обновляется.
- При прерывании: отчёт `IN_PROGRESS` или `BLOCKED`, если среда позволяет.
- Запросы создаются в момент обнаружения пробела (фаза 2), чтобы адресат мог начать раньше.

## 5. Права записи

| Файл | Права Asset Artist |
|---|---|
| `Asset_Artist/*` | владелец |
| `_Shared/REQUESTS/REQ-AA-*` | владелец шапки и раздела «Запрос»; раздел «Ответ» принадлежит адресату запроса |
| `_Shared/TASK_BOARD.md` | только свои строки |
| `_Shared/ARTIFACT_INDEX.md` | только строки своих ассетов |
| `_Shared/PROJECT_STATE.md` | только раздел «Графика» |
| `_Shared/CONFLICTS.md` | добавлять записи; закрывать только свои и только после решения пользователя или владельца входа |
| `_Shared/DECISIONS.md` | только добавлять `CONFIRMED`-решения |
| `Inputs/*` | только чтение |

## 6. Конкурентная запись
1. Перед записью в общий файл перечитай его.
2. Изменяй только свою часть. Используй точечные правки, не перезаписывай файл целиком.
3. Если среда поддерживает атомарную запись, проверку версии или блокировки, используй их.
4. Если файл изменился между чтением и записью и правки пересекаются с твоей частью, не перезаписывай. Сообщи о конфликте в отчёте и пользователю.

## 7. Защита решений
`CONFIRMED`-решения пользователя агент не меняет без явного разрешения. Агент может предложить изменение (`PROPOSED`) с описанием влияния.
