# ASSET_VALIDATION_SKILL — проверка и выдача

## Назначение
Не выдать потребителю ассет, который не соответствует требованиям, и выдать проверенный ассет предсказуемо.

## Триггер
Фазы 6–7 `WORKFLOW.md`, а также появление файлов в `Assets/_incoming/`.

## 1. Проверка
1. Для каждого ассета-кандидата пройди разделы B и C `QA_CHECKLIST.md`, для набора — раздел D.
2. Технические пункты проверяй инструментами, если они есть: размеры, альфа-канал, формат, вес, `viewBox`, имя.
   Пример: python/Pillow — `Image.open(p).size`, `.mode`, проверка полупрозрачных пикселей по краям.
   Нет инструмента — пункт получает `NOT_VERIFIED`, а не `PASS`.
3. Визуальные пункты: открой изображение, если среда позволяет. Для SVG сначала растеризуй. Проверь читаемость на целевом размере (уменьшенная копия) и в мокапе.
   Нельзя посмотреть — визуальный QA получает `NOT_VERIFIED`, ассет помечается «требует проверки человеком».
4. Ошибка → исправление → повторная проверка, до 2 итераций. Затем статус `FAILED_QA` с описанием.

## 2. Выдача
1. Сохрани файл по неймингу и версии из `OUTPUT_CONTRACT.md`. Существующие файлы не перезаписываются.
2. Заполни строку в `Assets/ASSET_MANIFEST.md`, все поля.
3. Статус `READY_FOR_REVIEW`. `APPROVED` ставится только после подтверждения пользователя, и при этом пересобирается `export/`.
4. Перечитай и точечно обнови:
   - `_Shared/ARTIFACT_INDEX.md`: строки своих ассетов;
   - `_Shared/TASK_BOARD.md`: свои задачи, плюс handoff-строка для `developer_agent` (основной потребитель) и других известных потребителей;
   - `_Shared/PROJECT_STATE.md`: раздел «Графика», кратко что готово и что заблокировано.
5. При изменении утверждённых ассетов (новая версия, `NEEDS_REVIEW`) отметь это в `TASK_BOARD.md` для потребителей.

## 3. Ошибки
- Конфликт записи в общий файл → `MEMORY_RULES.md`, раздел 6.
- Ассет нельзя выдать из-за `FAILED_QA` → в отчёт и в итоговое сообщение с причиной и предложением.

## Выход
QA-результаты в манифесте, выложенные файлы, обновлённые общие индексы.
