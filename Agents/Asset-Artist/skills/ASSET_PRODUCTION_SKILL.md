# ASSET_PRODUCTION_SKILL — план, style test, производство

## Назначение
Превратить Asset Brief в ассеты: выбрать метод под каждый ассет из реально доступных, проверить стиль на малом наборе, затем произвести остальное.

## Триггер
Фазы 3–5 `WORKFLOW.md`. Предусловие: нет открытого `BLOCKER-ALL`.

## 1. Определение возможностей (каждый запуск)
Проверь фактически, без допущений по названию среды:
1. **T2.** Есть ли в списке инструментов среды инструмент генерации изображений, например MCP Layer AI или другой. Запиши имя инструмента и поддерживаемые параметры: размер, прозрачность, референс-изображения, seed.
2. **Shell и утилиты.** Проверь наличие `python3 -c "import PIL"`, `magick`/`convert`, `rsvg-convert`, `python3 -c "import cairosvg"`, `node` + `sharp`, `sha256sum`.
3. **Просмотр изображений.** Может ли модель в этой среде открыть PNG и увидеть его.
4. **T1** доступен всегда, если можно писать файлы. **T3** доступен всегда.

Результат запиши в отчёт задачи в раздел «Возможности». Если T2 пропал между запусками, ассеты, запланированные под T2, получают статус `BLOCKED` или переводятся в T3. Это фиксируется решением, если затрагивает категорию.

## 2. План и выбор метода
Для каждого ассета: `AS-####`, имя, категория, состояния, базовый размер, плотности, метод, используемые рефы, статус.

| Тип ассета | Предпочтительно | Альтернатива |
|---|---|---|
| UI: кнопки, панели, рамки, иконки | T1 (SVG) | T2 |
| Тайлы, фишки, геометрические игровые объекты | T1 (SVG/Canvas) | T2 |
| Персонажи и существа в painterly / 3D-look стиле | T2 | T3 |
| Персонажи во flat/vector стиле | T1 или T2 по сложности | T3 |
| Иллюстративные фоны | T2 | T3 |
| Абстрактные / градиентные фоны | T1 | T2 |
| Простые статичные VFX (частицы, блики, вспышки) | T1 | T2 |
| Плейсхолдеры (greybox) | T1 всегда | — |

Правила:
- Метод должен выдерживать стиль из гайда. Если доступные методы стиль не выдерживают, тихо упрощать стиль нельзя. Ассет получает статус `BLOCKED`, а пользователю предлагаются варианты (`PROPOSAL`): T3, плейсхолдер, корректировка гайда.
- Анимация и спрайт-листы вне объёма (CD-07). Объект с анимацией в GDD получает статичные состояния, а в манифесте и отчёте пометку «анимация не сделана».
- Метод для целой категории записывается как решение (`DECISION_LOG_SKILL.md`).
- Позиции, выведенные агентом и отсутствующие в GDD или задаче, помечаются `PROPOSAL` и не производятся до подтверждения `game_designer_agent`, кроме style test.

## 3. Style test (гейт)
1. Выбери 2–3 самых показательных и рискованных ассета: ключевой игровой объект или персонаж, UI-элемент, фрагмент фона.
2. Сделай их выбранными методами по полной процедуре разделов 4–6.
3. Если есть средства, собери мокап: ассеты на экране в референсном разрешении.
4. Заполни `Assets/_style_tests/ST-###/STYLE_TEST.md` по шаблону `templates/STYLE_TEST.md`. Туда входят параметры, извлечённые из гайда (будущий `STYLE_PROFILE.md`), допущения и конкретные вопросы к ревьюеру.
5. Попроси утверждения у пользователя.
   - Утверждено: `STYLE_PROFILE.md` получает статус `CONFIRMED`, решение `DEC-AA-###` записывается.
   - Правки: новая итерация `ST-###` (до 3, затем эскалация с вариантами).
6. `STYLE_PROFILE.md` — это операционная выжимка из гайда. Гайду она не противоречит. Если для неё нужно что-то, чего в гайде нет, это `PROPOSAL` с запросом к `art_style_guide_agent` на обновление гайда.

## 4. T1 — код
- Рабочий исходник сохраняется в `Assets/_src/`. Он является каноническим источником для регенерации.
- **SVG:**
  - `viewBox` равен базовому размеру;
  - цвета только из `STYLE_PROFILE.md`;
  - без внешних ссылок и шрифтов (текст в кривые или без текста);
  - без растровых вставок, если не разрешено;
  - осмысленные `id`;
  - удалённые редакторские метаданные.
- **Canvas / процедурная графика:** детерминированный скрипт (фиксированный seed, если есть случайность) в `_src/`, экспорт в PNG через доступный рендерер.
- **Растеризация SVG:** через `rsvg-convert`, `cairosvg` или `sharp` с размерами из Format_Specs. Без рендерера SVG выдаётся как SVG, если это разрешено, иначе ассет получает `BLOCKED` с причиной «нет рендерера».
- Состояния объекта делай из общего исходника с параметрами, чтобы они оставались согласованными.

## 5. T2 — инструмент генерации
1. Собери структурированный промпт из `STYLE_PROFILE.md` и GDD:
   - объект и его функция;
   - стиль рендера;
   - палитра словами и, если инструмент принимает, hex;
   - обводка, свет и тени;
   - ракурс;
   - композиция и поля;
   - фон (прозрачный или однотонный под вырезание);
   - негатив: текст, водяные знаки, лишние объекты, фотореализм (если не нужен).
2. Референсы передавай только как стиль-референсы, если инструмент это поддерживает и это допустимо для данного рефа. Без имён художников и IP.
3. Генерируй 2–4 варианта за итерацию (CD-05: не больше 4).
4. Выбери вариант по разделам C и D `QA_CHECKLIST.md`. Если ни один не годится, сделай новую итерацию с исправленным промптом (до 3 итераций на ассет, CD-05).
5. Постобработай: вырезка фона, обрезка, ресайз (качественный ресэмплинг, без апскейла сверх исходника без пометки), плотности.
6. Сохрани в манифесте: инструмент, промпт, негатив, seed и параметры, выбранный вариант. Отклонённые варианты храни в `_src/<asset_id>/rejected/`, если они нужны для истории.

## 6. T3 — пакет промптов
1. Создай `Assets/_prompts/<asset_id>.md`:
   - промпт и негатив;
   - размер и соотношение сторон;
   - рекомендуемые параметры;
   - какие рефы прикладывать и зачем;
   - критерии приёмки (выдержка из QA_CHECKLIST);
   - куда положить результат: `Assets/_incoming/<asset_id>/`.
2. Статус ассета: `AWAITING_EXTERNAL`. Пункт попадает в итоговое сообщение («нужно от пользователя»).
3. Когда в `_incoming/` появились файлы: постобработка и проверка по `ASSET_VALIDATION_SKILL.md`. Файлы из `_incoming/` не перемещаются, а копируются в версионированный путь.

## 7. Итерации по фидбеку
`CHANGES_REQUESTED` означает новую версию того же `asset_id`. Фидбек цитируется кратко в `notes` манифеста. Предыдущая версия становится `SUPERSEDED`, когда новая утверждена.

## 8. Ошибки и эскалация
- Сбой инструмента: 2 повтора. Затем переход на другой метод, только если стиль выдерживается. Иначе ассет получает `BLOCKED`, сбой описывается в отчёте.
- Лимит генераций исчерпан: стоп. Сообщи, что сделано и сколько ещё нужно, и запроси разрешение.
- Вход оказался недостаточным в процессе работы: вернись в `INPUT_REQUEST_SKILL.md`, остальные ассеты продолжай.

## Выход
План в отчёте задачи, ассеты-кандидаты, исходники, пакеты промптов, `STYLE_TEST.md`, обновлённый `STYLE_PROFILE.md` (после утверждения).
