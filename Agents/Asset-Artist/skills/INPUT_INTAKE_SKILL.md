# INPUT_INTAKE_SKILL — чтение и проверка входов

## Назначение
Прочитать четыре входа, проверить их полноту для объёма задачи, найти противоречия и изменения с прошлого запуска.

## Триггер
Внутри `DISCOVERY_SKILL.md`, шаг 3, на каждой задаче.

## 1. Пути
По умолчанию (A-03):
- `Inputs/Art_Style/`
- `Inputs/GDD/`
- `Inputs/Format_Specs/`
- `Inputs/References/`

Если файлы найдены в другом месте (например, ссылка в `ARTIFACT_INDEX.md`), используй их и запиши фактические пути в `INPUT_REGISTRY.md`. Не ищи входы по всему диску.

Поддерживаемые типы: md, txt, pdf, docx, изображения. Если файл нельзя прочитать в текущей среде, он получает статус `UNREADABLE` и идёт в запрос с просьбой дать его в другом формате.

## 2. Процедура
1. Перечисли файлы в каждой папке.
2. Для каждого файла запиши в `INPUT_REGISTRY.md`: путь, размер, дату изменения и sha256, если есть shell. Добавь краткое резюме ключевых параметров (шаблон `templates/INPUT_REGISTRY.md`).
3. Сравни с прошлой записью. Изменившиеся параметры сопоставь с ассетами в манифесте. Затронутые ассеты получают статус `NEEDS_REVIEW`.
4. Проверь полноту по чек-листам из раздела 3, но только в объёме задачи. Например, если UI не в объёме, типографика для UI не нужна.
5. Проверь противоречия внутри каждого входа и между входами (раздел 4).
6. Передай результат в Discovery: пробелы с классами, конфликты, допущения.

## 3. Чек-листы полноты
Классы ниже — дефолтные. Если задача не затрагивает пункт, он не проверяется.

### Арт-стайл гайд (владелец: `art_style_guide_agent`)
| Пункт | Класс если нет |
|---|---|
| Стиль рендера: flat / vector / cel / painterly / pixel / 3D-look | BLOCKER-ALL |
| Палитра: основные и акцентные цвета, hex или образцы | BLOCKER-ALL |
| Обводка: есть/нет, толщина относительно размера, цвет | BLOCKER |
| Свет и тени: направление, число тонов, блики | BLOCKER |
| Язык форм: округлость/угловатость, пропорции персонажей | BLOCKER для персонажей |
| Уровень детализации на малом размере | NON-BLOCKING (дефолт: упрощать до читаемости на базовом размере) |
| Типографика UI (если текст в графике) | BLOCKER для ассетов с текстом |
| Примеры do / don't | INFO |

Если гайда нет, но есть рефы, агент может предложить черновой style summary по рефам. У такого черновика статус `PROPOSAL`, и он требует подтверждения. Гайд он не заменяет.

### GDD (владелец: `game_designer_agent`)
| Пункт | Класс если нет |
|---|---|
| Сущности и экраны, которым нужна графика, или явный список ассетов в задаче | BLOCKER-ALL |
| Функция каждого объекта: что игрок должен считывать | BLOCKER для объекта |
| Состояния: idle / pressed / disabled / selected / locked / destroyed / ... | BLOCKER для объекта |
| Число игровых типов и как они должны различаться | BLOCKER для типов |
| Ориентация экрана | BLOCKER для фонов и мокапа |
| Размер объекта на экране или сетка поля | BLOCKER |
| Эффекты и фидбек (статичные VFX-спрайты) | BLOCKER для VFX |
| Анимации | вне объёма (CD-07): делаются статичные состояния, в манифест и отчёт идёт пометка «анимация не сделана» |
| Сеттинг, персонажи, нарратив | NON-BLOCKING (влияет на содержание, не на технику) |

### Требования к ассетам и формату (владелец: `art_style_guide_agent`; параметры движка — `developer_agent`)
| Пункт | Класс если нет |
|---|---|
| Целевой движок / рантайм | BLOCKER для финального экспорта → запрос `developer_agent` (CD-04) |
| Базовый размер по типам ассетов или правило расчёта | BLOCKER |
| Форматы файлов и прозрачность | BLOCKER |
| Плотности (@1x/@2x/@3x) | NON-BLOCKING (дефолт: @1x и @2x) |
| Референсное разрешение экрана | NON-BLOCKING (дефолт: 1080×1920 portrait) |
| Нейминг и структура папок | NON-BLOCKING (дефолт: `OUTPUT_CONTRACT.md`) |
| Атласы для упаковки статичных спрайтов: нужны ли, размер, padding | NON-BLOCKING (дефолт: без атласов) |
| Лимит веса | NON-BLOCKING (дефолт: без лимита, с оптимизацией) |
| 9-slice, safe zones, pivot | BLOCKER для соответствующих UI-элементов |
| Цветовой профиль | NON-BLOCKING (дефолт: sRGB) |

Если Format_Specs не задают движок или параметры, которые от него зависят, спрашивай `developer_agent`, а не `art_style_guide_agent`. Такие параметры: поддерживаемые форматы, схема плотностей, 9-slice, pivot, атласы, нейминг для импорта. Дефолты `NON-BLOCKING` из таблицы выше используются до ответа и тоже включаются в запрос `developer_agent`.

### Референсы (владелец: `art_style_guide_agent`)
| Пункт | Класс если нет |
|---|---|
| Сами референсы | NON-BLOCKING (запрос, работа по гайду) |
| Пометка, что брать из каждого: палитра / форма / композиция / материал / настроение | NON-BLOCKING (запрос) |
| Привязка к ассетам или категориям | NON-BLOCKING |
| Что НЕ брать | INFO |

Референсы с узнаваемым IP разрешено использовать только по абстрактным качествам. Это отмечается в реестре.

## 4. Разрешение конфликтов
| Тип конфликта | Правило |
|---|---|
| Технический параметр (размер, формат, нейминг) | приоритет Format_Specs |
| Визуальный параметр: гайд против рефов | приоритет гайда; рефы не переопределяют гайд |
| Читаемость геймплея (GDD) против эстетики (гайд) | автоматического решения нет → `CONFLICT`, вопрос `art_style_guide_agent` и `game_designer_agent` в одном запросе; если их ответы расходятся — эскалация пользователю |
| Противоречие внутри одного документа | `CONFLICT`, вопрос владельцу документа |
| Вход против `CONFIRMED`-решения | решение действует; спросить владельца входа, устарел ли вход |
| Задача пользователя против входов | спросить пользователя в сессии |
| Ответ `developer_agent` против Format_Specs | `CONFLICT`, вопрос `developer_agent` и `art_style_guide_agent`; до решения финальный экспорт затронутых ассетов заблокирован |

Каждый `CONFLICT` записывается в `_Shared/CONFLICTS.md` (кто, что, где, затронутые ассеты) и включается в запрос.

## 5. Выход
- Обновлённый `INPUT_REGISTRY.md`.
- Списки пробелов, конфликтов, изменений и допущений для Discovery.
- Пометки `NEEDS_REVIEW` в манифесте, если входы изменились.
